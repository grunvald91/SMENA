### Выявленное и исправленное в ветке
1. Предпубликационный скрипт ранее допускал Node.js 18 — Vite 7 требует Node 20.19+ или 22.12+.
2. Проверки ранее не включали отдельную сборку рабочего экрана `kiosk-dist` и локальную SQLite симуляцию.
3. Старый порядок запуска мог публиковать код до появления новых таблиц; теперь миграции `--local --safe` до `push`.
4. Сценарий выкладки блокируется без `SMENA_BACKUP_VERIFIED=1` и `SMENA_MIGRATION_REVIEWED=1`.
5. Одновременное принятие заявок использует CAS; если прерывается `approving`, владелец при следующем открытии заявок запускает ограниченную по давности 10-минутную сверку: подтверждённая активная карточка завершает запрос, отсутствие карточки возвращает в очередь. Без фонового планировщика.

### ОБЯЗАТЕЛЬНЫЕ проверки, которые в этом окружении сделать нельзя

**В Codespaces, без сервера и GitHub Actions:**

```bash
git switch feat/org-access-foundation-20261011
npm ci --no-audit --no-fund
bash scripts/tgcloud_preflight.sh
```

Скрипт выполняет `node --check` на всех модулях/веб-коде/тестах, `npm run check` с полным Node test runner, локальный SQLite backup/restore и `npm run build`, `npm run build:kiosk`. Сборки должны создать `dist/index.html` и `kiosk-dist/index.html`.

**Telegram Serverless (отдельно, перед выкладкой):**
- Проверить выбранный бот/CLI авторизацию, `tgcloud status`, `tgcloud diff`, `tgcloud migrate --dry-run --local` и классификацию **всех** различий БД. Никаких destructive/manual/warning без отдельного решения.
- Сделать **проверяемый реальный бэкап Telegram SQLite** и пробное восстановление в безопасном контуре.
- `tgcloud run` с тестовыми данными для новых хендлеров/эндпойнтов, проверить работу `api.getChatMember`, `chat_shared`, `request_chat`, поддержку big integer ID.
- Проверить с настоящего Android/iOS: создание бизнеса, привязку группы, приглашение сотрудника, одобрение ставки, перепривязку рабочего компьютера без камеры, QR смены, selfie, фото в правильный чат, отчёт и фотоконтроль.

# ServGo Смена — запуск в Telegram Serverless

**Состояние:** код хранится в `grunvald91/SMENA`. Техническое размещение выполнено: бот `@servgo_smena_bot`, Mini App https://app8926504673.tgcloud.ai/ . Созданы 13 таблиц и настроен webhook. Подробные проверки и оставшиеся шаги — в [IMPLEMENTATION_STATUS.md](IMPLEMENTATION_STATUS.md).

## Важное ограничение архитектуры

Telegram Serverless **не обращается к серверу ServGo**. Обработчики, персональные настройки, табели, база SQLite и передача фотографий в рабочую Telegram-группу выполняются на стороне Telegram. `smena.servgo.ru` теперь работает как отдельный статический QR-экран с локально подписанными кодами; он не обращается к базе Telegram. См. [SUBDOMAIN.md](SUBDOMAIN.md). Нельзя полагаться на внешние вызовы Telegram Serverless в базу ServGo. Если позже потребуется самостоятельный веб-кабинет на домене, сначала проектируется отдельно защищённая идентификация и согласованный канал синхронизации; публичные endpoints Telegram Mini App напрямую с постороннего сайта не доступны.

## Что сделать в @BotFather

1. Через `/newbot` создайте нового бота; сохраните его username.
2. Откройте **My Bots → нужный бот → Serverless → Enable** (раздел доступен при включённом доступе к Telegram Serverless).
3. Там же найдите **Serverless → CLI Access → Access token**. Это *не* обычный HTTP Bot API token. **Не присылайте секрет в переписку, GitHub, Issue или Pull Request.**
4. Позднее, после первого `tgcloud push`, возьмите точный URL `https://app<app_id>.tgcloud.ai/` из ответа CLI и задайте его как **Main Mini App** этого бота в @BotFather. Для текущих QR-ссылок вида `https://t.me/<username>?startapp=scan_<token>` наличие Main Mini App обязательно.

## Развёртывание без GitHub Actions

Откройте `grunvald91/SMENA` в GitHub Codespaces и запустите встроенный терминал (достаточно Node.js 18+). Выполните:

```bash
npm install --no-audit --no-fund
bash scripts/tgcloud_preflight.sh
npx --no-install tgcloud login
bash scripts/tgcloud_deploy.sh
```

При `tgcloud login` отдельный CLI-токен вводится **только в терминале Codespaces**. CLI сохранит его в `.tgcloud/credentials`, директория исключена из Git. Вместо интерактивного входа можно создать GitHub Codespaces secret `TGCLOUD_TOKEN` с доступом только к репозиторию SMENA. **Не использовать обычный Bot API token вместо CLI token.**

`tgcloud_deploy.sh` не запускает GitHub Actions. Скрипт проверяет тесты и сборку, выводит `tgcloud status`, выполняет `migrate --dry-run --local`, затем делает `push`, `migrate --safe` и `webhook sync`. Он не использует `--force` и не удаляет ожидающие Telegram-обновления. В случае конфликтов, ручных или рискованных миграций **остановитесь и проверьте состояние**; не используйте `--yes` и `--drop-pending` автоматически.

После публикации посмотрите `tgcloud status`, `tgcloud webhook` и оставшиеся изменения `tgcloud migrate --dry-run`. В BotFather настройте Main Mini App по адресу, выданному `push`.

## Начальная настройка в Telegram

1. В личном чате нового бота: `/start`, затем `/setup Название организации`.
2. Добавьте бота в рабочую группу (или отдельную группу для каждой точки). Владелец должен быть администратором группы; он вводит `/bind Название точки`.
3. Сотрудники пишут `/id`; владелец в личном чате бота добавляет их через `/employee TG_ID 350 Имя`.
4. Создайте утреннюю и вечернюю смены: `/shiftadd 1 Утренняя 09:00 15:00 5`; `/shiftadd 1 Вечерняя 15:00 21:00 5`. Назначьте сотрудников через `/shiftassign СОТРУДНИК_ID СМЕНА_ID YYYY-MM-DD` или Mini App.
5. На доверенном рабочем устройстве владелец открывает Mini App, регистрирует устройство для точки и оставляет QR-экран открытым. Для QR нужен работающий WebCrypto в целевой среде; при отсутствии безопасных криптографических примитивов код обязан отказать, а не пропускать проверку.
6. На своём телефоне сотрудник сканирует QR, выбирает приход/уход, делает селфи через камеру Mini App. Бот должен отправить снимок в привязанную рабочую группу и только после этого зарегистрировать отметку.
7. Проверьте: старый QR отвергается, второй приход запрещён, уход без новой отметки невозможен, комментарий к раннему/позднему уходу обязателен, `/report` и `/problems` доступны только владельцу.

## Необязательный внешний сайт

`smena.servgo.ru` **опубликован как QR-экран рабочего места с HTTPS**. Telegram Mini App размещается на выделенном Telegram домене, а вызовы `Telegram.WebApp.Serverless.call` защищены Telegram initData. Для прямого самостоятельного кабинета в обычном браузере нужен другой способ авторизации, а доступ к данным Telegram не следует выдумывать.

## Что пока не подтверждено

- Сборка в Codespaces и запуск sandbox проверены. ECDSA/JWK sandbox не поддерживает; для проверки подписи используется локально встроенный P-256 verifier. WebCrypto на клиентском телефоне ещё требует проверки.
- `tgcloud push`, миграция и webhook выполнены. Main Mini App в BotFather включён, getMe вернул has_main_web_app: true.
- Сквозная доставка фото из камеры Mini App в нужную группу, ограничения на размер payload и работоспособность на Android.
- Подходящая юрисдикция хранения персональных данных сотрудников, условия хранения фотографий и допустимость применения в коммерческом кадровом учёте.

Для запуска с реальными персональными данными сначала проверьте законность обработки и требуемые согласия. До этого используйте тестовую организацию и фиктивные данные.

# Дорожная карта: простое подключение ServGo Смена (11 октября 2026)

**Статус:** утверждённый для планирования последовательный проект. Ни один пункт ниже не считается реализованным только потому, что задача заведена.

## Цель

Сделать подключение новой точки с помощью трёх видимых действий владельца:

1. «Создать бизнес» или «Подключить существующий ServGo».
2. «Выбрать рабочую группу» — подтверждённый выбор чата Telegram с автоматическим предложением названия точки.
3. «Подключить рабочий экран» — владелец своим телефоном сканирует код с экрана компьютера/планшета.

Сотрудники приглашаются по ссылке и подтверждаются владельцем, график назначается по необходимости. Система не должна заставлять вводить Telegram ID, chat ID или device ID. Дополнительные функции должны быть доступны после базового подключения.

## Текущая основа, которую нельзя сломать

- Рабочий бот: @servgo_smena_bot, Telegram Serverless, собственная SQLite и Mini App.
- https://smena.servgo.ru уже используется как **рабочий QR-экран**, а не общедоступный админ-кабинет; не заменять этот экран непротестированным кабинетом.
- Сотрудник сканирует QR телефоном, снимает живое селфи телефоном, фотография/комментарий идут в привязанную группу.
- Утренняя/вечерняя/ночная смены, причины отклонений, ручные отчёты, фотоконтроль остаются работоспособными.
- **Рабочее устройство может не иметь камеры**. Никакой camera permission или приложение на рабочем устройстве не требуется.
- Telegram Serverless не зависит от прямого доступа к VPS, MySQL/PostgreSQL или API ServGo.
- Никаких фоновых планировщиков, автоматических напоминаний или GitHub Actions.
- Секреты и зарплатные данные не публиковать в рабочих группах.

## Уточнения технического решения

### Соединение рабочего устройства

На рабочем экране в браузере создаётся неэкспортируемый приватный ключ. QR регистрации переносит его публичную часть и одноразовые параметры **на телефон владельца**. Telegram Mini App использует `showScanQrPopup`, получает весь payload, подтверждает права владельца и сохраняет публичный ключ у себя. Не полагаться на `?start=` или `?startapp=` для передачи длинного публичного ключа: параметры deep links ограничены по длине. Рабочий экран использует стабильный идентификатор, вычисленный из канонической формы публичного ключа, и локально подписывает короткоживущие QR сотрудников. Прямой обратной связи от Telegram Serverless к экрану без нового канала нет: подтверждение показывается владельцу, а рабочий экран может показывать ожидание первой успешной проверки.

Обеспечить версионированность ключей и совместимость уже зарегистрированных устройств. Потерянное устройство отзывается владельцем без старой подписи с дополнительной проверкой права и аудитом. Запретить старый публичный ключ. Ключ браузера — **не** доказательство аппаратной уникальности или физического присутствия. Активные QR могут быть переданы удалённо.

### Группа и организация

Выбор чата через Telegram `request_chat`/`chat_shared` или официальные Mini App механизмы. Отдельно проверить фактическое членство и разрешение бота отправлять фото. Название чата — предложение имени точки, но chat и location остаются разными сущностями (одна точка может сменить группу, одна организация может иметь много точек). Исключить автоматическое доверие всем участникам группы.

### Сотрудники и график

Присоединение сотрудника по приглашению; Telegram identity связывается с уже имеющимся сотрудником после проверки владельца. Допускаются несколько назначений на дату, замены и переносы; без назначения не начислять автоматически несуществующие часы. Не нарушать историю ставок/смен; отклонения сохраняются с фактическим временем и причиной.

### Синхронизация с ServGo

Проверить технически Telegram Bot-to-Bot Communication между реально используемыми ботами, включить только для них. Сейчас обработчик SMENA отбрасывает `from.is_bot`; для доверенного канала понадобится узкий маршрут при сохранении запрета для остальных ботов. Сохранить устойчивую карту идентификаторов: ID организации/сотрудника в SMENA ↔ ID в ServGo. Основные источники: ServGo для каталога бизнеса и карточки персонала, SMENA для табелей и фактического времени, booking_bot для расписания клиентов. Не делать слепую двустороннюю запись по названиям.

Каждое сообщение несёт event_id, версию, источник, целевой бизнес, тип операции; получатель проверяет подлинность, разрешённость и возвращает подтверждение **применения**. Сохранить исходящие/входящие журналы, обработку повторов, ручное восстановление после разрыва, ограничение циклов. Канал не должен пересылать селфи и зарплаты без отдельного обоснования.

## Definition of Done для любого этапа

1. Проверяемая схема БД и контроль доступа по каждой организации.
2. Юнит-тесты + проверки предыдущих сценариев, реальный smoke-тест, где возможен.
3. Безопасная миграция, откат и подтверждение сохранности существующих записей.
4. Понятные кнопки для пользователя, инструкции для ИИ в AGENTS.md и чистый журнал изменений.
5. Изменения сперва в отдельной ветке, тесты, затем ручная выкладка без GitHub Actions. Не считать развернутым, пока Telegram/VPS подтвердили результат.

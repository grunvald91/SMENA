# Этап P1.1 — безопасный выбор организации (без изменения старых команд)

- Добавляется отдельная таблица `user_organization_selections` (user_tg_id PK, org_id, updated_at). Вносится **только предпочтение пользователя**, которое каждый раз сверяется с серверным списком действующих ролей.
- Чтение `listMyOrganizations` возвращает `organizations`, `selectedOrganization`, `selectionRequired`. Для единственной доступной организации выбор происходит автоматически; для нескольких — без явного выбора операция с контекстом новой организации не должна запускаться.
- `selectOrganization` устанавливает предпочтение, используя Telegram initData и разрешение `organization.view`; пользователь никогда не может выбрать чужую организацию.
- Текущие функции `/report`, `/setup`, `/bind`, зарплаты, QR, фотоконтроль **пока** пользуются прежней проверкой владельца. Никакой скрытой подмены бизнес-контекста не делается. Кнопку переключения активного бизнеса на живом интерфейсе показывать только ПОСЛЕ миграции каждой функции, иначе действия могут попасть в другой бизнес.
- Нынешний индекс `organizations.owner_tg_id UNIQUE` сохраняется: множественное владение организациями требует отдельной рискованной миграции и проверенного восстановления.

## До публикации

1. `npm ci && npm run check && npm run build && npm run build:kiosk` в Codespaces.
2. Резервная копия базы и **проверка восстановления**. Если восстановление невозможно проверить — не применять опасные миграции.
3. `tgcloud migrate --dry-run --local` должен показывать только CREATE TABLE новых таблиц/индексов `organization_memberships`, `user_organization_selections` и `onboarding_sessions`. Удаление UNIQUE, ALTER существующих таблиц, удаление данных — блокер.
4. Под отдельным тестовым Telegram пользователем проверить: единственная организация выбирается; две требуют выбора; manager имеет доступ только к своей организации; чужие или отозванные членства отклоняются; старые команды и QR работают без изменений.
5. Вся работа до реальной проверки — только отдельная ветка/PR. GitHub Actions не использовать. Прямая связь Serverless→ServGo VPS не добавляется.

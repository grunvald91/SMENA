# SMENA — baseline и начало этапа P1
11 октября 2026. Ветка: `feat/org-access-foundation-20261011`.

## Зафиксировано по репозиторию
- Бот работает на Telegram Serverless, собственная база и Mini App; `smena.servgo.ru` используется как отдельный QR-экран, а не кабинет зарплат.
- Рабочее устройство может **не иметь камеры**. Сотрудник снимает селфи со своего телефона.
- Организации, сотрудники, смены, фотографии, отчёты и фотоконтроль уже существуют. Сохранять идентификаторы и историю.
- В `organizations.owner_tg_id` имеется уникальность. Один владелец пока не может создать два собственных бизнеса.
- По `docs/IMPLEMENTATION_STATUS.md` ранее были платформенные проверки; **этим PR production или серверный бэкап не проверялись**.

## Что вводится без разрушения старой схемы
Новая таблица `organization_memberships` с `org_id`, `user_tg_id`, `role`, `status` и аудитными полями. Старая схема `organizations` и owner-only операции пока неизменны.

Legacy-владелец получает права по прежнему `owner_tg_id`. Дополнительные членства учитываются только для действующих организаций и активных записей с известной ролью.

Новый endpoint `listMyOrganizations` показывает только доступные бизнесы, без зарплатных и личных сведений. `manager` не получает `payroll.view` и `roles.manage`; `employee` не получает прав управления.

## Что ещё не реализовано
- Несколько собственных бизнесов на одного владельца (требуется осторожное устранение уникального индекса после проверки данных).
- Переключение активного бизнеса и явный org scope **во всех** существующих сервисных операциях.
- Интерфейс кнопочного онбординга и создание/отзыв ролей.
- Бэкап и восстановление live DB, cloud `tgcloud migrate --dry-run`, реальные camera/Telegram smoke-тесты новой версии.

## Обязательные проверки перед выкладкой
1. В Codespaces: `npm ci --no-audit --no-fund`, `npm run check`, `npm run build`, `npm run build:kiosk`.
2. Проверить доступное резервное копирование базы и **восстановление**.
3. `tgcloud migrate --dry-run --local`: ожидается **только** создание `organization_memberships` и индексов. Любой DROP/перестройка существующей таблицы — стоп.
4. На тестовом боте: владелец видит свою организацию, управляющий вторую, чужая недоступна. Проверить права API, QR, селфи, комментарии, смены, отчёт, фотоконтроль.
5. Только после проверки — ручная публикация через Codespaces без GitHub Actions. Serverless никогда не должен зависеть от вызовов VPS ServGo.

Дальнейшее развитие: миграция многовладельческого режима → безопасный явный контекст бизнеса на всех endpoint → кнопочный мастер и привязка чата → сотрудники/устройства → Bot-to-Bot sync.

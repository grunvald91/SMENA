# QR рабочего места — smena.servgo.ru

Статус на 10.10.2026: https://smena.servgo.ru/ опубликован; HTTPS проверен. Это рабочий QR-экран, а не внешний зарплатный кабинет.

## Привязка группы

1. Владелец в личном чате @servgo_smena_bot отправляет `/setup Название организации`.
2. Добавляет бота в рабочую группу; разрешает ему отправлять сообщения и фото. Сам владелец должен быть администратором группы.
3. Отправляет в группе `/bind@servgo_smena_bot Название точки`. Бот сохраняет ID группы сам. Для проверки вручную передавать ID не обязательно.
4. Сотрудник получает свой Telegram ID через `/id`; владелец добавляет его в личном чате `/employee 123456789 350 Александр Петров` (ID → ставка в рублях за час → имя; ID получается через /id; также принимается ID → имя → ставка). Если заданы шаблоны смен, сотруднику нужно назначение на дату.

## Привязка рабочего устройства

1. На устройстве, которое остаётся на точке, открыть https://smena.servgo.ru/ и нажать «Настроить это устройство».
2. Скопировать публичный код `pk1_`. Он не содержит приватного ключа.
3. Владелец в Mini App бота выбирает точку, вставляет код в «QR-экран на smena.servgo.ru» и нажимает «Привязать рабочий экран».
4. Ввести выданный ID устройства на сайте, указать название точки и нажать «Показать QR».
5. Оставить страницу открытой. QR действует 30 секунд и заменяется каждые 25 секунд. Использовать постоянный профиль браузера и автоматическое время; не чистить данные сайта.

Один активный ключ на точку. Для замены на старом сайте: «Настройки экрана» → «Отвязать устройство». Код `kr1_` действует 60 секунд; владелец подтверждает его в Mini App. Потеря старого ключа требует отдельной процедуры восстановления, которой пока нет.

## Отметка

Сотрудник открывает Mini App → «Сканировать QR», наводит камеру Telegram на рабочий код, выбирает приход или уход, при необходимости добавляет комментарий и делает селфи. Обычное открытие ссылки QR также работает. Поддержка встроенного сканера зависит от клиента Telegram (Bot API 6.4+). Комментарий доступен всегда, при уходе вне графика обязателен; комментарии видит только руководитель в истории смен. Время определяется сервером Telegram при выборе действия; камера не сдвигает время отметки. Фото направляется в привязанную группу; после записи смены подпись содержит приход/уход, сотрудника, название точки, дату и время с UTC-смещением, при уходе — отработанную продолжительность. Зарплаты и комментарии к отклонениям в группу не публикуются.

Название рабочей точки редактируется владельцем в Mini App: выбор точки → «Изменить название точки». Названия шаблонов смен и внутренние ID в подпись фотографии не выводятся.

## Как работает без прямого соединения с VPS

Сайт хранит только свой неэкспортируемый P-256-ключ в IndexedDB браузера и ID устройства. Он локально подписывает ID, текущую секунду и случайный 96-битный nonce. Подпись нормализуется к low-S. Ссылка Telegram содержит версию, ID, время, nonce и 64-байтную подпись, а не запрос к VPS.

Telegram проверяет зарегистрированный публичный ключ, срок кода, активность устройства и сотрудника, затем создаёт запись QR в своей базе. Возраст кода <30 секунд; будущий timestamp допускается только в пределах 5 секунд. Прямого подключения Telegram Serverless к VPS или его базе нет; секреты бота и персональные сведения на сайте не хранятся. Наличие ключа не доказывает физическую геолокацию и не предотвращает пересылку актуального QR.

## Выкладка и проверка

`npm run check` → `npm run build` (Mini App) → `npm run build:kiosk` (отдельная статическая сборка kiosk-dist). Модули/mini app публикуются через tgcloud push; kiosk-dist — отдельно на VPS. nginx root: /var/www/smena-servgo/current; релиз: /var/www/smena-servgo/releases/20261010-57ad748. Сертификат Let's Encrypt SAN smena.servgo.ru; существующий certbot обновляет его, отдельный deploy hook перезагружает nginx после обновления этого домена. Бэкап предыдущей nginx-конфигурации: /root/smena-deploy-backup-20261010/nginx-before.tar.gz. GitHub Actions не используются.

35 тестов прошли. На платформе проверены приход/уход на синтетических данных, отказ чужому сотруднику, подмена подписи, повторное открытие и отзыв устройства; фото этим тестом не отправлялось. В браузере проверено создание/сохранение ключа. Реальное QR → камера → доставка фото → подтверждение группы остаётся проверить на телефоне с зарегистрированным рабочим устройством. По сообщению пользователя, группа уже привязана; повторный /bind не нужен.
